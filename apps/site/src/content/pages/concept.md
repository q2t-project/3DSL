# Concept

3DSL は、**全体を保ったまま局所へ入り、局所から全体へ戻れる知識空間**をつくるための表現・探索システムです。

複雑な対象を一枚の固定図へ押し込むのではなく、全体での位置づけ、局所の構造、関係、粒度、観点を往還しながら読みます。

## 1. 何のためのものか

3DSL の中心は 3D 表示そのものではありません。

- 全体の中で「いま何を見ているか」を失わない
- 局所の要素・関係・働きを調べる
- 全体へ戻って別の場所と比較する
- 配置や接続に無理があれば、表現そのものを見直す

という探索を支えることが目的です。

## 2. なぜ 3D を使うのか

3D は条件付きの表現手段です。

複数の関係、粒度、スコープ、観点を一つの全体に保つために空間の自由度が役立つ場合に使います。

- すべての対象に 3D が必要だとはしません
- 三つの軸があらゆる分野で同じ意味を持つとはしません
- 座標・色・向き・frame などの見た目だけから、対象世界の意味を自動的に導きません

位置や軸に意味を持たせる場合、その読み方はモデルごとに明示される必要があります。

## 3. 誰が使うのか

最初の公開段階では、**Reader / Explorer** を第一の利用者とします。

複雑な対象について、

> これは全体のどこにあり、何とつながり、内部では何が起きているのか

を往還しながら確かめたい人が主な対象です。

モデルを作る **Author / Mapper** は第二の利用者です。Modeler は重要ですが、Library / Viewer の価値を理解する前提にはしません。

## 4. このサイトの入口

- **Library**：具体的なモデルから 3DSL の価値を知る入口
- **Viewer**：全体と局所を往還してモデルを探索する
- **Concept / Docs**：読み方、考え方、仕様、運用を確認する
- **Modeler**：モデルを構成・編集する作者向けの経路（後段）

初めての場合は [Library](/library) からモデルを選び、[Viewer](/app/viewer) で開いてください。

## 5. 3DSS との関係

3DSS は、3DSL で選ばれた表現情報を保存・交換するための JSON 形式です。

3DSS が schema-valid であることは、元資料の意味がすべて保存されていることや、表示された関係が正しいことを自動的には保証しません。

3DSL の Product 定義と、3DSS / Runtime / Renderer の実装契約は分けて扱います。

## 6. Library の役割

Library は sample file の置き場ではありません。

具体的なモデルを通して、

- whole ↔ local
- 配置と比較
- 異なる図式の接続
- 説明経路

を実際に試す場所です。

無料の Library / Viewer だけで、3DSL の中心的な体験を評価できることを目標にします。

## 7. 現時点で保証しないこと

次は今後の検証課題です。

- 3DSL が文章や 2D 図より一般に理解を改善すること
- 空間配置が必ず新しい発見を生むこと
- すべての分野に一つの普遍的な座標系を適用できること
- 表示結果や公開モデルの内容が専門的に正しいこと

利用可能な表現と、認知効果・理論的正しさ・商業的価値は別々に評価します。
