# Concept

3DSL は、複雑な知識を一つの固定した画面へ押し込めるためのものではありません。  
**全体を保ったまま局所へ入り、局所から全体へ戻る**ための、空間的な知識探索の仕組みです。

## 1. 何を支えるか

読者は、ある項目について次の問いを行き来します。

- 全体のどこに位置するか
- 周囲と何でつながるか
- 内部では何が起きているか
- 見る粒度・範囲・観点を変えると何が変わるか
- もう一度全体へ戻したとき、理解がどう更新されるか

3DSL は、その往還中も全体構造を外部に保持し、再参照できるようにすることを重視します。

## 2. なぜ三次元を使うのか

3D は目的でも、すべての対象に必要な前提でもありません。

階層、局所構造、複数の関係、異なる粒度や観点などを、同じ全体の中で区別して配置するために三次元空間が有効な場合に使います。

- 三軸の意味はモデルごとに異なり得ます
- 距離や方向が意味を持つ場合は、その解釈を別途示す必要があります
- 3D で表示できることだけでは、理解の改善や対象世界の正しさを証明しません

## 3. Library と Viewer

**Library** はサンプルファイル置場ではなく、3DSL が何をできるかを具体例から理解するための入口です。

**Viewer** では、一つのモデルについて全体を見て、対象へフォーカスし、局所を調べ、再び全体へ戻ります。

標準の読者導線は次です。

```text
Library
→ Diagram / context
→ /app/viewer
→ whole
↕ local
→ return / compare / continue
```

内部の `/viewer/*` は Viewer runtime / preview 資産であり、公開プロダクトの入口は `/app/viewer` です。

## 4. 配置は仮説である

位置、向き、色、frame、境界、接続は、見た目だけで対象の意味を決めません。

モデルの配置から何を読むかは、そのモデル固有の説明・出典・解釈契約に依存します。

```text
visual difference != domain fact
UUID != target-world identity
frame != target-world time by default
axis label != universal 3DSL axis
```

## 5. 3DSS の役割

3DSS は、3DSL の構造表現を保存・交換するための機械可読な形式です。  
Viewer は 3DSS を読み込みます。

ただし、

```text
3DSL Product != 3DSS schema
schema-valid != semantic complete
```

です。読者向けの説明経路や、モデル固有の軸・frameの読み方などは、3DSS 本体とは分けて扱います。

## 6. 読者と作者

Release 1 の主役は **Reader / Explorer** です。

作者側では、配置・接続・比較を行う過程そのものが、新しい区別や不足した接続に気づく契機になり得ます。  
Modeler はそのための重要な資産ですが、Library / Viewer の公開を待たせる前提にはしません。

## 7. この段階で主張しないこと

現時点では、次を一般的事実としては主張しません。

- 3DSL が文章や2D図より常に優れている
- 3D表示が一般に理解を改善する
- 空間配置が必ず新しい発見を生む
- すべての分野が同じ三軸で表せる

これらは、表現を作れることとは別の検証課題です。
