# 3DSL Product Principles v0.1

Status: `APPROVED / PRODUCT_DEFINITION_V1`

## P1 — Preserve the whole
Local exploration should not silently replace the structure the user came from.

## P2 — Structure before spectacle
3D interaction, animation and effects are justified only when they clarify structure, relation, scale, scope or viewpoint.

## P3 — 3D is conditional, not dogmatic
3DSL should use three-dimensional space where it materially supports the model.
It must not claim every subject requires 3D or that every axis has universal meaning.

## P4 — Placement is interpretable
A meaningful position, direction, color, frame or boundary needs an interpretation.
A visual difference is not automatically a domain fact.

## P5 — Reader entry matters
Dense whole-model views need explanation routes or clear entry points.
The product should not require expert reconstruction before it becomes useful.

## P6 — Library demonstrates value
The primary public proof of 3DSL is a set of good explorable models, not a feature list.

## P7 — Authoring supports discovery, but comes later
Modeler is important because constructing a model can expose distinctions and connections.
It is not a prerequisite for the reader-facing release.

## P8 — Preserve uncertainty and provenance
Unknown, external, provisional and source-derived information should not be silently converted into false certainty.

## P9 — Product before implementation
Schema, runtime architecture and existing code do not define the product.
Implementation follows Product → Architecture → Code.

## P10 — Validate claims separately
A usable representation, a novel construction method, improved human understanding and commercial value are separate claims and need separate evidence.
