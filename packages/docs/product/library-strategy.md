# 3DSL Library Strategy v0.1

Status: `APPROVED / PRODUCT_DEFINITION_V1`

## Role

Library is not a sample-file list.

It is:

> the place where a user learns what 3DSL can do by entering concrete, explorable models.

## Library item requirements

Each public item should ideally provide:
- a clear title and subject;
- a short question or reason to explore;
- enough context/source information to understand what is represented;
- a direct Viewer entry;
- an optional explanation route;
- provenance/rights appropriate to the content;
- a visible relationship to one or more core 3DSL capabilities.

## Core capability coverage

The Library as a whole should demonstrate:

1. whole ↔ internal structure;
2. spatial placement and comparison;
3. connection of heterogeneous diagram structures;
4. explanation routes through a shared whole.

Later examples can demonstrate:
5. condition/scenario differences;
6. cross-domain or collaborative atlas structures.

## Domain breadth

Candidate public categories:
- Mathematics
- Philosophy
- Law
- Science
- Engineering
- Systems
- Language
- Experimental

Breadth should demonstrate generality without implying every domain shares one fixed ontology or axis meaning.

## Free Library role

Free content should be sufficient to:
- understand the product;
- experience the core Viewer;
- see more than one structural pattern;
- judge whether 3DSL is useful.

## Premium Library role

Premium should add depth, completeness, specialized curation, source work or high-value domain content.

Premium should not be required merely to discover what 3DSL is or whether the core Viewer is useful.

## Curation principle

Quality is not model size.
A small model with a clear structural question can be more valuable than a dense model with no entry route.
