# 3DSL User Flow v0.1

Status: `APPROVED / PRODUCT_DEFINITION_V1`

## Primary reader flow

```text
Home
 ↓
One-sentence product meaning
 ↓
Representative example
 ↓
Library
 ↓
Choose diagram
 ↓
Diagram detail / context
 ↓
Open Viewer
 ↓
Whole view
 ↓
Follow explanation route or explore
 ↓
Open local structure / inspect relations
 ↓
Return to whole
 ↓
Compare another region / diagram
 ↓
Return to Library
```

## First 30 seconds

A first-time visitor should learn three things:

1. **What:** 3DSL is a way to explore complex knowledge as a connected spatial whole.
2. **Why:** it keeps the whole available while the user enters local structure and returns.
3. **How:** choose a Library example and open it in Viewer.

The first screen should not require understanding 3DSS, schema, coordinates or Modeler.

## Reader interaction loop

```text
orient
→ focus
→ inspect
→ return
→ compare
→ re-orient
```

The interface may guide this with an authored explanation route, but free exploration remains possible.

## Author flow

Later-stage:

```text
Library example
→ understand conventions
→ decide to create
→ Modeler
→ place / connect / inspect
→ validate
→ save / export
→ publish or share through an appropriate content workflow
```

Modeler is reached after product value is understood, not before.

## Failure conditions

The user flow fails if:
- the visitor sees controls before understanding the purpose;
- Library feels like a file/sample dump;
- Viewer opens without enough context to know what to inspect;
- moving into detail loses the user's sense of the whole;
- 3D interaction becomes the task instead of understanding the represented structure.
