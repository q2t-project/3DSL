# 3DSSで図を設計する

読み手が図から答える問いを一つ書きます。例えば「乾燥試料から2時間で水がいくら出たか」のように、比較する対象と範囲を決めます。問いに必要な点・線・面、軸、数字を選び、見た人が元の根拠に戻れるようにします。

| 適用する場面 | 決める・確認すること |
|---|---|
| 3DSSのファイルを作る | `document_meta` にタイトル、文書UUID、作成・更新日時、作者、作品版、形式の固定URIを記録し、使用した要素の必須属性を埋める。 |
| 図を制作・共有する | 読み手の問い、必要な対象と関係、配置に意味を持たせる範囲、位置から何を読めるかを点検する。 |
| 軸、数量、比較が問いの答えを担う | 軸の原点と単位、観測の対象・境界・時点、比較で揃える条件を記録する。局所の意味は `coordinate_contexts`、比較は `comparisons`、値は `quantities` で図に対応付けられる。 |
| 色・柄・線種が意味を担う | 作品内の `visual_legend` に意味と適用範囲を記録し、要素から参照する。形、配置、短い語などで読み直せるようにする。 |
| グリッド、部品、拡張で読みやすくする | 必要に応じて補助要素、GLB、数式などを使う。保存形式には使用したものだけを書く。 |

フィールドの条件と構造検査は[3DSS仕様](/docs/spec/latest/)を参照してください。

## 座標で何を読むか

世界座標のX・Y・Zに対し、作品で「何が違うか」を宣言します。分類の軸では所属、順序の軸では前後、計量軸では基準と換算から値を読みます。分類や順序の間隔は描画上の間隔です。

例えば、学問分野の比較でYを用途の順、乾燥工程の部分図でYを実時間とする場合は、それぞれの局所原点、軸、適用先を記録します。量・質・時間の枠を使う場合は、どの量、どの質の区別、どの時間かを明記します。視点や認識の枠を使うときも、何を受け取る・何を判断する・何を基準にするかを分野に即して特定します。

## 関係と文字

端点に対象のUUIDを指定すると、対象を選んで関連へ進めます。表示上の位置だけが要る端点には座標を指定します。面の途中への取付には面UUIDと面内位置を使います。対象を動かしてから、本来の相手に線が続くか見ます。

方向のある関係には、どちらからどちらか、何を意味するかが分かる矢印とキャプションを付けます。軸に平行な線を使う図では、向きから一つの差が読める配置を優先します。途中に曲がりが必要な場合は、媒介となる対象や区切りに意味があるかを見直します。

文字面は原則として座標軸の一つに直交させます。位置や状態を示す語は横組み、方向に沿って過程をたどる語は必要に応じて縦組みにします。矢印付きの縦組みは、字の上 `up` と逆向きに、語の先頭から末尾まで矢印と同じ順で進むようにします。回転後も文字列単位で振る舞いを確かめます。文字サイズには16・8・4・2のような倍々の段階を使い、遠景から局所へ何を読ませるかを揃えます。

## 量と収支

量には、何の値か、対象とその境界、符号、単位、時間の基準を記録します。量軸に沿った長さと基準位置を決め、量に使わない横幅を表示上の余白として扱います。

| 何を示すか | 形の使い分け |
|---|---|
| 時点値 | 時間軸に直交する厚みゼロの面。残高や保有量のほか、温度のような観測値にも使える。 |
| 一件の量または増減 | 事象の位置から量軸に伸びる端印付きの線。正負は基準の上下、移転の向きは対象間の接続にそれぞれ記録する。 |
| 期間の合計 | 合計の高さを区間末の輪郭で、集計範囲を時間軸の括弧で示す。平均や率を描く場合は集計方法と単位を明示する。 |
| 記録されたゼロ・欠測・適用外 | ゼロには基準位置の輪などを設ける。欠測と適用外は状態をラベルや情報欄に示す。 |

同じ期間・対象・単位を使うと、保有量の変化を出入りと照合できます。乾燥試料が20 kgから12 kgへ変わり、水が外へ出るだけの設例では、差の8 kgを蒸発量として読めます。芯から表面への移動は試料内部で起き、全体の収支では相殺されます。途中の率を描く場合は、その時点または区間の観測値と単位を記録します。

## 複式と相殺の表示

| 読ませる意味 | 図で照合する方法 |
|---|---|
| 借方・貸方 | 同じ仕訳の明細を借方・貸方の列に置き、借貸の表示と共通の仕訳参照を付けて両辺の合計を照合する。青・赤を使うときは、固定した正面と適用範囲を凡例に示す。 |
| 勘定の増減と物の移転 | 勘定の増減は基準からの正負で示し、現金・製品などの移転には送り手、受け手、向きが分かる線を使う。 |
| 報告範囲での消去・除外 | 元の残高、対象となる範囲、調整額、報告結果をたどれるようにする。面の斜線を使う場合は、調整や除外の対象となった箇所を凡例で示す。 |
| 純額がゼロ | ゼロの表示から、どの境界で何を差し引いたかをたどれるようにする。個々の流れや残高はそれぞれ参照を持つ。 |

連結の例では、期末には個社の債権・債務が各12万円あり、連結報告での消去結果が各0円です。決済後は個社の残高自体が各0円になります。同じ0円でも、異なる根拠を指せるようにします。ハッチングは面に付ける柄として記録でき、柄の意味は作品内の凡例で決めます。

## 開き直して確かめる

1. 使用したスキーマの固定版で形式を検証し、端点・面・凡例・数量・比較が対応する要素を指すか見ます。
2. 実際にViewerで回転・拡大して、文字、矢印、量の基準、比較条件が図から読めるか確認します。スマホ幅と、色を使えない場合でも試します。
3. Modelerで編集、保存、再読込を行い、同じUUIDと値、接続、面と文字の姿勢が残るか照合します。元資料と編集を保存する手順は[制作と保存の案内](/docs/usage/create-save-read/)を参照してください。

図の説明を読んだ結果と、実操作で確かめた結果を制作記録に残します。
