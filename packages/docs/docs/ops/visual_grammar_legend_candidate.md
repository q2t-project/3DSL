# 文字の凡例候補：HG-V1 の意味設計と比較見本

作成：2026-10-30。対象は `apps/reconstruction/ssot/legend_lab/model.3dss.json`。

この文書は、文字面・縦横・書体・色・サイズの役割を人間が比較するための候補を記録する。HG-V1 の受入前であり、3DSL 全体の文法や公開スキーマを確定する文書ではない。既存の食事モデルは変更せず、新しい候補スキーマ `v2.0.0` と独立した比較見本を使う。

見本の範囲は「文字面の読み方を比べること」。位置は説明のための配置であり、米の主経路の +Y に工程順序を持たせる範囲だけを明示する。q・Q・t の全座標に意味を割り当てた完成済みの共通軸モデルとは扱わない。

## 意味の割当て

| 表現手段 | この見本で担う役割 | 担わせない意味 |
|---|---|---|
| 文字を置く面 | どの次元の組合せから読むか | 特定の単語が永久に属する分類 |
| 横組・縦組 | その場で捉える／方向に沿って追う、という読み方 | 縦組だけで時間の向きや因果を確定すること |
| 文字サイズ | どのスコープで先に見せるかという相対階層 | 数量・価値・絶対的な重要度 |
| 書体 | モデル本体の語と、作者が読み方を述べる注記の補助的区別 | 真偽・確実性・具体／抽象の普遍的分類 |
| 色 | 関係系列を追う補助 | 点の排他的な所属、測定量、座標軸 |

本文は `noto-sans-jp`、注記は `noto-serif-jp`。太さはすべて 400 とし、この見本では太さに新しい意味を割り当てない。注記は必ず「注：」から始め、単一書体でも注記であることを残す。色は線に使い、点と線の文字は共通の明るい色にする。

共通化を検討するのは各表現手段の役割までである。具体的な色と関係系列の対応はこの作品の凡例であり、黄系が物質、紫系が役割、青緑系がエネルギーであるという普遍的対応を定めない。

## 文字面・時間・書字方向

既存の軸案 `q=+Z`、`Q=-X`、`t=+Y` をこの比較見本で採用する。ただし、対象を測定済みの量・質・時間の数値グラフに変換するものではない。

| 読む側面 | 文字面 | front / up | 書字 | 見本 |
|---|---|---|---|---|
| 状態・構成 | XZ = qQ | +Y / +Z | 横組 | 家の米、ご飯、調理役 |
| 量の時間的な維持・配分 | YZ = qt | +X / -Y | 縦組 | 保管、取り分け |
| 性質の時間的な変化 | XY = Qt | +Z / -Y | 縦組 | 炊飯 |

旧試作 `meal_prototype.3dss.json` の「XY＝時間を捨象した役割・種類」という対応は継承しない。XY は Qt であり、時間を含む。この修正を既存の全作品へ自動適用することもしない。

**状態が時点を持つことと、状態の文字面が時間軸を含まないことは両立する。** 状態の文字はある段階を切り出した面であり、前後の切片は過程を介して接続される。「炊く分の米」と「残す分の米」は同じ Y に置き、「注：同じ切片」と表示する。

同じ XZ 面でも、調理役はある時点の具体的な人の状態ではない。「注：役割の型」と表示し、時点を置かない役割の記述として読む。「電気〔種類〕」も供給時点や供給量を記録したストックではない。状態／型を面だけから判定しない。

保管を qt 面へ置く理由は、数量を保つという時間的維持の側面を読むためである。米の性質の変化をすべて否定する意味ではない。取り分けは数量の配分という側面を読む。炊飯を Qt 面へ置く理由は、生米からご飯への性質変化を読むためである。炊飯にも量的な側面はあり、この見本がすべての側面を尽くすとはしない。

縦組は局所座標の上から下へ読む。この見本の過程語では `up=-Y` とすることで、文字列の進む方向 `-up` を `+Y` に合わせる。横組文字列の全体を 90 度回す処理とは区別する。カメラの回転で字面や書字方向を自動補正せず、記録された pose を保つ。

## 小さな食事見本

10 個の意味点、2 個の注記点、10 本の関係線を使う。表示フレームは全体を示す 0 のみ。注記点はモデルを説明する文字であり、食事に参加する対象や工程ではない。

| 点 | 表示文字 | サイズ | 読解 |
|---|---|---:|---|
| 保管前の家の米 | 保管前の米 | 8 | 保管前の状態 |
| 米の保管 | 保管 | 16 | ストックを保つ時間的な維持 |
| 保管後の家の米 | 家の米 | 16 | 取り分け前の状態 |
| 米の取り分け | 取り分け | 8 | 数量を配分する過程 |
| 炊飯に取り分けた生米 | 炊く分の米 | 8 | 取り分け直後の切片 |
| 取り分け後に残す生米 | 残す分の米 | 8 | 同じ切片の残す枝 |
| 米を炊く過程 | 炊飯 | 16 | 性質変化の過程 |
| 炊飯後のご飯 | ご飯 | 16 | 炊飯後の状態 |
| 調理を担う役割 | 調理役 | 16 | 時点を置かない役割の型 |
| 電気というエネルギーの種類 | 電気〔種類〕 | 8 | 時点を置かない種類の記述 |

図全体から先に読む語を 16、配分の枝や関係を近づいて読む語を 8 とした。この大小はこの見本での相対的なスコープである。今後の作品で同じ語が必ず同じサイズになるとはしない。線の関係語と注記も 8。サイズを読める最小値へ一律にそろえず、拡大や選択情報によって読める経路を用意する。

主経路は保管前の米、保管、家の米、取り分け、炊く分の米、炊飯、ご飯を接続する。取り分けから残す分の米を分岐させ、家の米すべてが炊飯へ入るという読みを避ける。調理役は取り分けと炊飯へ「担当」で接続する。電気は炊飯へ「エネルギー」で接続する。

調理役の UUID は既存試作と同じ `f225f07d-b1ab-5ece-8834-d60b3726bec7` を使う。他の UUID はこの独立見本のもの。これは既存モデル全体の移行ではない。

## 色と多重参与

| 系列 | この見本の線色 | 色なしでも残る手掛かり |
|---|---|---|
| 米の経路 | `#E8B86D` | 対象、保管後、炊く分、残す分、結果、接続端点、矢印 |
| 役割の参与 | `#C4A9F5` | 担当、調理役からの接続、矢印 |
| エネルギーの参与 | `#62CDD5` | エネルギー、電気からの接続、矢印 |

すべて実線。線種に追加の意味を持たせる比較は今回行わない。炊飯には三系列が接続するが、炊飯の文字を混色したり、一つの系列色へ固定したりしない。多重参与は接続として残す。線の矢印はその関係の向きであり、担当線まで時間経過や物質移動として読まない。

座標軸の X=青、Y=緑、Z=赤とは別の局所凡例である。軸を表示する場合も、軸名と軸線・ギズモの位置から役割を区別する。選択表示でこれらの意味色を塗り替えない。

## 座標で述べること・述べないこと

米の状態と過程の +Y は工程の順序のみを表す。間隔は経過時間ではない。炊く分と残す分は同じ Y に置く。枝を離す X の差から米の量や性質の差を数値として読まない。

q と Q は文字面を読む次元として使い、この見本では測定した数量や性質の尺度を座標へ割り当てていない。役割・種類の位置は担当や供給が起こる時刻ではない。注記の高さは読みやすい余白であって量の値ではない。文字面の規約と、未記録の座標値の意味を区別する。

重量、割合、保管期間、消費電力量、人物・器具の同一性、台所の物理配置、厳密な保存則は追加しない。水や炊飯器等は今回の比較を小さく保つために省き、この見本だけで炊飯の必要条件をすべて記述したとは扱わない。

### P4 の食事モデル反映時に決めること

- 文字面だけでなく位置にも意味を持たせる範囲を、作品のスコープごとに決める。数量の未測定を、任意の高さが量を表してよい理由にはしない。
- 状態・過程の発生を時間順へ置く領域と、役割・種類を記述する領域の読みを明示する。役割の表示位置から担当時刻を推定させない。
- 測定値、順序だけを記録した値、読みやすい配置を区別し、未記録の値を埋めない。区別を記録する契約が必要になった場合だけ追加を検討する。
- サイズの階層を、食事モデル全体で何をどのスコープから読ませるかに合わせ直す。見本の 16／8 の対応を、単語ごとの永久規則としてコピーしない。
- この見本で省略した材料・道具等を戻した際に、多重参与、残米の枝、型と切片が引き続き読めることを確認する。

## 比較で保持するもの

UI の比較段階では、文字面、位置、サイズ、接続、関係語、作者注を保持する。縦横、書体、線色を段階的に有効にして、各手段が読みへ何を加えるかを見る。これは作者のモデルを保存し直す操作ではなく、一時的な表示比較である。

- 共通書体でも「注：」を残す。
- 色をなくしても関係語、接続、矢印を残す。
- 大小の比率を維持し、選択で文字の階層を変更しない。
- 選択や情報表示によってモデルを隠さない。
- 凡例の sample は表示用の例であり、各要素の appearance を継承・上書きする指定ではない。

カラーバリアフリーのために色を捨てるのではなく、色が識別できれば追跡が速くなり、識別できなくても関係を読める候補を検討する。代償は、関係語や注記が増える表示面積、混雑、凡例の学習量である。全要素を同じ強さで前景化するとサイズによるスコープを損なうため、拡大・情報欄等の補助と分けて評価する。

## HG-V1 で判断すること

1. 状態・維持・質変化・役割を、この文字面と縦横の組合せで区別する方針を採るか。
2. 書体は本体／作者注、色は関係系列に担わせる方針が、図を読む助けになるか。
3. 同じ XZ 面の状態と型を、スコープを示す語や「注：」で区別できるか。

候補スキーマの検証、端点参照、pose、サイズ等の自動確認は必要だが、それだけを人間の読解の合格とは扱わない。HG-V1 の意味上の選択と、後段の実機での読み・操作の検証を分ける。現時点では作者の受入、初見者の理解、スマホでの読みやすさを確定していない。
