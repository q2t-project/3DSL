# 食事モデル：文字の向きによる読み分けの試作

更新：2026-10-30。対象は `apps/reconstruction/ssot/models/meal_prototype.3dss.json`。21点・23線の未公開試作であり、3DSL全体の新しい軸規約を確定する文書ではない。

今回の狙いは、米の状態、時間を持つ過程、時刻を置かずに述べる役割・材料・道具を、文字の向きと接続から読み分けられるようにすること。任意の奥行きや物理的な台所の配置を付け足す変更ではない。

## 文字の向きと記述の範囲

| この図での読み方 | 文字面 | 保存する姿勢 | 代表例 |
|---|---|---|---|
| ある段階の状態。この例では米・ご飯のストック | XZ | `front=[0,1,0]`, `up=[0,0,1]` | 家の米、取り分けた米、残した米、ご飯 |
| 時間のある過程。変化する場合と維持する場合を含む | YZ | `front=[1,0,0]`, `up=[0,0,1]` | 購入、運搬、保管、取り分け、炊飯、配膳 |
| 時間を捨象した役割・材料・道具の記述 | XY | `front=[0,0,1]`, `up=[0,-1,0]` | 調理役、水、電気、炊飯器 |

状態とストック、状態変化とフロー、時間的と非時間的は、一つの排他的な三分類ではない。米の状態は工程上の時点を持つ。保管は時間を持つが、ここでは状態を維持する過程として読む。人・水・道具そのものに時間性がないとは述べていない。一般的な過程を時間を捨象して記述することもできるが、今回の過程点はこの食事の前後を持つ例として置いている。

この図でフローとして読む変化は運搬だけでなく、購入による所有の移り、取り分け、炊飯による状態変化、配膳も含む。流量の測定値、速度、会計上の厳密なストック／フロー式は導入していない。

既存の「構造と分類」モデルでは「状態」が `[16,0,0]`、`front=+Y/up=+Z`、「状態遷移」が `[16,16,0]`、`front=+X/up=+Z` にある。この二面と方向の符号を継承した。役割等をXY面へ置く対応は本作の局所規約である。この面の文字の上向きは-Yとし、+X/+Y/+Z側の斜視で上下逆に投影される+Yの案を修正した。面の区別を維持した作者側の配置であり、カメラへ追従させる描画ではない。`3DSS_spec.md` §6.5の `text_pose` をそのまま使い、スキーマは変更しない。

## 配置で読めること

米の状態と過程はZ=0の領域に置く。この領域の+Yは工程の前後だけを表す。間隔は経過時間の長さではなく、文字の大きさや点の半径も米の量を表さない。

主な米の経路はX=0、取り分け後に残す枝はX=-80とする。残した米と炊飯に取り分けた米はともにY=0であり、取り分け直後の同じ切片として読む。Xの差は枝の区別で、量の大小・材料の性質・重要度の数値ではない。

役割・材料・道具の記述はZ=75の別の層に置く。この層のX/Yは項目を並べるための配置であり、時刻や物理的な所在ではない。Z=75も抽象度の連続尺度ではなく、時間を捨象した記述を別の層として識別するための位置である。層をまたぐ線が、役割や種類と具体的な過程との対応を示す。

初期の斜視を+X/+Y/+Z側に置くと、三つの文字面を同時に見られる。視点を動かしても姿勢は作品に記録されたまま保つ。すべてをカメラへ向ける表示にすると、この読み分けが失われる。裏側で文字を鏡像にしない描画上の扱いと、作品の姿勢を変更することは別である。

+Y方向から正対すると、工程の前後が視線方向へ重なり、複数の状態の文字が重なる。この視点は状態の面を見る切片として使い、全工程を同時に読む初期視点にはしない。正対への自動切替は行わず、全体の前後を読むときは斜視を使う。

## 経路と関係の変更

| 変更 | 読み取れる区別 |
|---|---|
| 「購入・運搬」を購入と運搬へ分け、購入後の米を間に置く | 所有・入手の変化と、場所の移動を分ける |
| 到着した米、保管、保管後の家の米を接続する | 保管を、瞬間のストックや物の変換と同義にしない |
| 取り分けから「炊く分」「残す分」へ分岐する | 家の米すべてを炊飯へ送ったという読みを避ける |
| 水→炊飯を「材料」とする | 材料としての使用を、道具やエネルギーから分ける |
| 電気→炊飯を「エネルギー」とする | 材料・道具と異なる参与として読む |
| 炊飯器→炊飯を「道具」とする | 道具を材料と同じ入出力にしない |

水・電気・炊飯器の点は、時間を捨象した種類の記述である。その線は今回の炊飯との対応を述べる。個別の水のストック、投入量、供給期間、特定の炊飯器の同一性はまだ記録していない。「調理役」が複数の過程へ接続していても、同じ一人がすべてを担うとは確定しない。

初期の390px画面で文字が小さかったため、点文字のサイズを7から13、線文字を4.5から6へ変更した。表示名は「炊く米」「残す米」とし、正式名と読解説明は保持する。線は「対象」「結果」「担当」「材料」「エネルギー」「道具」「炊く分」「残す分」の短い役割語を使い、具体的な意味は線の作者メモで補う。三つの姿勢、点の配置、同時点の残米分岐は変更しない。

状態と過程の間の線ラベルはYZ面、役割・種類と過程を結ぶ線ラベルはXY面に置く。矢印はその線に書いた対象・結果・担当・使用の方向を読むためのもの。すべての線が時刻の進行や物質の流れを意味するわけではない。

既存の17点のUUIDは保持する。「購入・運搬」の点は購入へ限定し、新たなUUIDで運搬と中間状態を追加した。既存18線のUUIDも保持し、分離に伴い「到着後」の両端と「保管後」の向きを明示し直した。保存済みの選択を同じUUIDで開けるが、旧複合点の意味が完全に同一のままとは扱わない。購入と運搬の担当線、残米の枝など5線を追加した。

## 検証と留保

静的検査では、実配布の厳格validator、点と線のUUID、参照先、四表示の端点閉包、三姿勢、残米と炊く分の同じYを確認する。ブラウザの読みやすさ・タップ・視点は別途実表示で確認する。姿勢とデータ構造の合格を、作者による表現の受入や利用者の読解確認へ読み替えない。

2026-10-30のモデル単体検査で、実配布の厳格validator、全44要素のUUID重複なし、四表示の端点閉包、文字のfront/upの直交を確認した。ブラウザの検証結果はViewer側の検査記録で扱う。

この版は、字面と関係から区別を読めるかを検討する候補である。量・質・時間への還元、測定していない数量・重量、厳密な保存則、個人・器具の同一性、調理や食事の全過程は追加していない。
