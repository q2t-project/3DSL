# 作品の改訂・訂正の運用

3DSLのアトラスと解説は、調査・検証と表現の改善に応じて継続的に改訂します。各公開版について対象範囲と根拠を確かめ、以前の版を読んだ人が必要な変更を確認できるようにします。

本書は3dsl.jpに掲載する作品の改訂運用の正本です。登録作業は[作品の登録・更新手順](/docs/library/workflow/)、表示は[作品詳細ページの表示方針](/docs/library/page-policy/)に従います。読者向けには[作品の更新・訂正について](/docs/usage/updates-and-corrections/)を案内します。

制定日：2026年11月22日。

## 1. 変更の重要性を判断する

変更の重要性は、編集量や変更した属性の種類ではなく、読者が対象・関係・条件・結論をどう理解するかへの影響で判断します。

| 変更の種類 | 判断の例 | 公開する記録 |
|---|---|---|
| 軽微な修正 | 意味に影響しない誤字、重なりの解消、操作性の改善 | 公開単位でまとめて記録できます。個別のお知らせは不要です。 |
| 増補 | 対象、論点、具体例、出典の追加 | 何を追加し、扱う範囲がどう広がったかを短く記します。 |
| 資料・状況の変化への対応 | 法改正、新しい統計、対象の状況変化 | 何が変わり、どの時点・範囲の資料を反映したかを記します。 |
| 解釈・構成の見直し | 分類、軸の意味、概念間の関係の再整理 | 変更点と理由を記します。従前の整理も成立する場合は、誤りの訂正と区別します。 |
| 誤りの訂正 | 関係の向き、数値、出典の読み違いの修正 | 誤っていた点と修正内容を記します。理解・判断に実質的な影響があれば、第4節の重要訂正として扱います。 |

位置、軸、関係の両端・向き、所属、階層、意味を担う文字姿勢や大小を変えるときは、読み取れる意味を再確認します。線一本の修正でも理解が変わる場合があります。意味を維持した余白や重なりの調整は、軽微な修正として扱えます。

改訂のたびの謝罪文は求めません。誤りの訂正を単なる増補や表示改善として記録せず、読者が理解を改める必要のある箇所を示します。

## 2. 作品の版と日付を区別する

| 情報 | 記録する場所・意味 |
|---|---|
| 作品の版 | `model.3dss.json` の `document_meta.version`。作品データの版を識別します。 |
| 作品の改訂日時 | `document_meta.revised_at`。作品データを実際に改訂した日時です。 |
| 初回公開日時 | `_meta.json.published_at`。初めて公開した日時を保持します。 |
| 更新公開日時 | `_meta.json.republished_at`。解説・添付などを含む掲載内容の更新公開を示します。 |
| 資料の基準日・確認範囲 | 出典の説明や作品の解説に記します。法令・統計など、対象時点が理解に影響する資料について示します。 |
| 保存形式の版 | `document_meta.schema_uri` が指す3DSSの固定版です。作品の版とは別です。 |
| 表示に使うアプリの版 | 必要な検証記録に残します。Viewerの更新だけを理由に、作品の内容を改訂したとは扱いません。 |

公開する作品データを変更したら、作品の版と改訂日時を更新します。同じ作品版に異なる作品データを上書きしません。公開までの微調整は一つの版にまとめられます。形式だけを移行した場合も、その変更と、意味の変更の有無を記します。

専用ガイドや解説に独立した公開版がある場合は、原本の版と区別して表示し、対応する成果物を記録します。既存の別採番を、同じ番号だったかのように書き換えません。共通の作品ページに表示する「3DSS原本の版」は `document_meta.version` に対応します。

作品データを変えず、解説や掲載情報だけを変更した場合は、作品の版・改訂日時を変更せず、更新公開日時と更新履歴に記録します。解説の変更で図の読みや結論が変わる場合は、図との整合も再点検し、変更した成果物を履歴で識別します。資料を確認していない範囲まで、最新の状態を確認したとは表示しません。版や日付の記録を増やすために、新しい必須JSON項目は設けません。

## 3. 読者向けの更新履歴を残す

作品ごとの主要な変更は、`packages/3dss-content/library/<id>/content.md` の「更新履歴」にまとめます。主要な改訂・訂正を公開する際に本文がなければ、この用途のために用意します。既存の履歴がある場合は、その続きに追記します。

一件の記録には、更新公開日、対象となる作品版、変更の種類、何が変わったかを記します。解釈の見直しや訂正では理由と影響する範囲も添えます。解説だけの改訂は、そのことを明記します。版番号だけで変更の意味を推測させないようにします。

次は記入形式の例です。実作品の日付や変更事実を示すものではありません。

```md
## 更新履歴

### YYYY-MM-DD ／ 作品版 x.y.z

- 変更の種類：増補／資料の更新／構成の見直し／訂正など
- 変更内容：読者が何を新しく、または異なって読み取れるか
- 理由・影響範囲：必要な場合に記載
```

作業上の全変更を列挙する必要はありません。非公開の制作記録は、公開してよい根拠と読者に必要な説明を確認してから要約します。

## 4. 重要な誤りを訂正する

以前の版から得た主要な理解や判断を改める必要がある誤りは、重要訂正として扱います。通常の増補を待たず、判明した範囲の訂正または確認中の範囲を知らせます。

訂正記録には、次を残します。

- 影響する旧版。範囲を特定できなければ、その未確認範囲。
- 誤っていた箇所と内容。
- 修正後の内容と訂正理由・根拠。
- 読者の理解・判断に影響する範囲。
- 訂正を公開した日と、訂正版の作品版。解説のみの訂正はその旨。

作品情報や解説の冒頭など、読者が気づける場所にも短い案内を置き、詳しい訂正記録へつなぎます。解説が折りたたまれている場合は、その外からも訂正の存在に気づける掲載箇所を用意して、公開前に確認します。これは表示上の要件であり、履歴からの自動抽出や専用の通知機能が実装済みであることを意味しません。モデルの操作面を覆わず、操作前の毎回確認も求めません。目立つ案内の掲載範囲は影響に応じて判断し、案内を整理した後も訂正記録を辿れるようにします。

通常の案内先は作品ページと更新履歴です。把握している特定の利用先に重大な影響がある場合は、対象を絞った個別連絡を検討します。本規定だけを根拠にメッセージを自動送信せず、宛先と送信の指示を別途確認します。

## 5. 保存版と配布ファイルを扱う

主要な公開版は、作品データ・解説と、意味の確認に必要な表示情報を対応付けて保管します。保存版を公開する場合は、対象版と最新版の案内先を明記します。全編集の差分表示、全旧版の常時公開、定期更新を一律の義務にはしません。

固定した旧版の内容を、後から同じ版のまま書き換えません。旧版に関する訂正は、旧版への案内ページや更新履歴から確認できるようにします。提供していない保存版や固定URLを、利用可能であるかのように案内しません。

今後配布する単体HTMLには、作品名、作品の版、改訂日、正規作品URLを、作品情報などから読める形で残します。3DSSでは `document_meta` の作品識別・版・日時を保持し、正規作品URLへの案内を既存の `reference` 欄など使用する形式が許す場所に残します。既存の出典を消さずに記載し、`_meta.json.links.canonical` の正規作品URLと照合します。保存・編集・配布できる範囲は、引き続き[作品ごとの利用条件と共通の利用条件](/policy/content-usage/)に従います。

同じ作品版として提供する3DSS、専用HTML、解説の対応を公開前に確認します。既に利用者の端末へ保存されたファイルの自動更新や回収は前提にしません。

## 6. 公開前に確認する

1. 直前の公開版と今回の変更を比較し、第1節の種類と重要性を判断します。
2. 必要な版・日付・資料基準日を更新し、初回公開日を保持します。
3. 主要変更を更新履歴へ追記し、重要訂正には気づける案内を付けます。
4. 必要な旧版を保管し、配布物の版と最新版の案内先を照合します。
5. 作品ページ、専用HTML、配布ファイルを実際に開き、記録した変更と表示が一致するかを確認します。登録・配備は[作品の登録・更新手順](/docs/library/workflow/)に従います。

2026年11月22日以降の新規公開・改訂から本規定を適用します。既存作品で不足する履歴や配布物の案内は、次の改訂時に整えます。既知の重要な誤りは、第4節に従って扱います。

導入以前の履歴は、確認できる公開記録・保存物に基づく範囲だけを掲載します。記録のない版・変更理由・公開日時を推定で補わず、「未記録」または「確認できず」と示します。作業コミットの日時だけから公開日時を決めません。
