# 3DSL Monetization v1

Status: `APPROVED / PRODUCT_DEFINITION_V1`

## Product principle

The first monetization experiment should validate willingness to pay without obscuring the core product value.

## v1 boundary

### Free
- core site and concept explanation;
- core Viewer access;
- documentation / 3DSS specification;
- representative Library examples across several structural patterns;
- enough content to evaluate the product.

### Premium
- deeper or more complete curated domain models;
- higher-value source integration / commentary / supporting materials;
- specialized content collections.

The boundary is primarily **content depth/value**, not “basic navigation vs usable navigation”.

## Why this fits the roadmap

The roadmap places Library + Viewer before Premium validation.
Therefore a user must be able to experience the core 3DSL value before payment.

## Current implementation note

Existing/unmerged Premium mechanisms are implementation evidence, not the product boundary.
Token/cookie/external-payment mechanics may remain a practical first delivery method if later architecture review supports them.

## Deferred business decisions

Not decided in this phase:
- subscription vs one-off purchase;
- creator marketplace;
- paid Modeler;
- team/collaboration plans;
- API licensing;
- enterprise/private deployment.

These require actual demand evidence.
