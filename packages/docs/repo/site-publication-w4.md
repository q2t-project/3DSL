## 問い合わせの確認範囲

既存の Formspree エンドポイントへ通常 HTML POST で送る経路を維持し、`target="_blank" rel="noopener"` で受付サービスを別タブに開く。認証情報、通知先、契約内容はソースに追加しない。URL の `?sent=1` だけで受付済みと表示しない。CAPTCHA を含む確認・受付結果はサービス側で確認し、元ページには入力を残す。JavaScript が無効でも同じ通常 POST を使える。

当初の同一ページ AJAX 方式は採用しない。サービス設定と成功応答の形式が未確認のため、JSON を推測判定して受付済みと表示する処理を除去した。JavaScript が有効な場合は通常 POST の開始後に送信ボタンをロックし、明示操作でだけ解除する。解除しても入力を消去せず、再送もしない。入力欄は無効化しないため POST の項目が欠けない。元ページで受付完了を断定せず、確認画面が開かない場合や通信断も自動再送しない。

コード検査は通常 POST と JavaScript 無効時の経路、必須入力・メール・空白本文、項目保持、二重操作、明示解除、ローカル成功推定がないことを対象にする。実 handler の疑似実行であり、実サービスの受付・実受信成功を示さない。

Formspree 管理画面はこの実行環境では未ログイン。フォーム所有者、通知先、有効状態、ドメイン制限、利用枠、CAPTCHA 設定と実受信は未確認。本人が所有者・通知先を確認した後、識別できるテスト1通で受付画面・サービス側記録・受信箱を照合する。外部へのテスト送信はこの変更では行っていない。
